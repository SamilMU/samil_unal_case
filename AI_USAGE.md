# AI Collaboration & Usage Report

**1. Explain the terms context, prompt, skill, and agent as they relate to AI coding assistants.**
* **Context:** The specific information, files, code snippets, or rules provided to the AI so it understands the constraints and current state of the project.
* **Prompt:** The actual human-written (or in this case, created via another LLM that consumed human-written prompt) instruction sent to the LLM to trigger a specific task.
* **Skill:** A specific, specialized capability of an AI model, such as generating boiler plate code, reviewing files for improvements in any kind of matter. In the case of test automation, an example would be "creating a bare-bones Cucumber test file and creating the step implementations with placeholder values" and this could be stored and used as a skill for new functions. 
* **Agent:** An autonomous AI system that can iteratively execute tasks, trigger other sub-agents if it is permitted, evaluate its own output, and use external tools (like executing a terminal command) to achieve a broader goal without constant human prompting. It can be specific to a task to achieve narrower goal which would means less token consumption and less prone to making a mistake or it can be vice-versa. 

**2. How did you validate the AI output? Which parts did you reject and why?**
I validated the AI output primarily through runtime execution using Pytest, rather than just static code analysis. While I accepted the structural generation of the Page Object Model methods, because the the creation of framework was already something that is worked at and it is scalable, most of the times the suggestions were mostly true and covered most of the effort that would be required for a task, I also rejected some parts of the AI's initial attempt at the "Software Development" test scenario. It failed to include the last verification method that is used in the same manner the previous test, even though the previous test was explicitly given as a reference to the new test in the prompt.  

**3. Describe one point where the AI was weak in this task and how you solved it manually.**
The AI was inherently weak at mapping accurate CSS locators because it lacks live, rendered DOM access to the Insider One website. During the UI generation, it hallucinated a `job_item_position_department` locator that did not exist on the live page. I solved this manually by running the test, analyzing the failure trace, correcting the locator logic.

**4. In which situations would you prefer to write code manually instead of using AI?**
I rarely prefer complete manual coding but I would prefer to use the "code-completion" and "code-suggestion" rather than complete usage of AI when architecting the foundational framework (like setting up `conftest.py` fixtures or base utility classes) because AI often defaults to basic, monolithic scripts rather than scalable patterns. It is eager to write the solution to a problem rather than thinking about how can it be solved scalably and extensibly. I also prefer similar manner of coding for highly complex, undocumented business logic where the AI would require more time to context-switch than it would take for me to write the code myself, but even in those scenarios, I would still be acting as a human-in-the-loop.. If it is explicitly forbidden or bad practice to use LLM's in the setting (sensitive info, company software behavior etc.), then I code manually.
